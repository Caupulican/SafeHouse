# Pi-hole adlists — one URL per line, loaded by ../scripts/load-blocklists.sh.
#
# Ads, tracking, malware. These are general-purpose lists. The in-app / mobile ad SDK
# coverage that matters for Google Play Games is applied at AdGuard Home instead —
# see ../adguard/filters.json.
#
# HaGeZi's `hosts/` directory was retired upstream; those URLs now 404. Discovered
# 2026-08-19, by which point `hosts/pro.txt` and `hosts/pro.plus.txt` had been serving
# Pi-hole's THREE-WEEK-OLD CACHED COPIES — `pihole -g` logs "using previously cached
# list" and exits 0, so a dead list looks exactly like a healthy one and nothing in the
# dashboard says otherwise. Check the URLs, not just the run's exit code:
#
#     docker exec pihole pihole-FTL sqlite3 /etc/pihole/gravity.db \
#       "select address from adlist where enabled=1;" | xargs -I{} \
#       curl -s -o /dev/null -w '%{http_code} {}\n' -L {}
#
# The `adblock/` variants are the live equivalents. They are ABP syntax (`||domain^`),
# which Pi-hole v6 parses natively and which covers subdomains per line, so the raw
# domain COUNT drops while coverage does not — do not read the smaller number as a
# regression.

# ADULT / NSFW COVERAGE — NOT SHIPPED. ADD YOUR OWN.
# ---------------------------------------------------------------------------
# This repo ships no adult-content blocklist: not the domains, and not a URL pointing
# at them. The right list differs by household and by jurisdiction, it is not this
# project's place to curate or redistribute one, and a stale list committed here would
# give a false sense of coverage — the worst outcome for a control like this.
#
# To add one, append a single line below with a list of your choosing. Any
# hosts-format or domain-list URL works. Several blocklist projects publish
# well-maintained ones; pick one you are willing to audit, and read what it blocks
# before pointing a family's DNS at it.
#
#     https://example.invalid/your-chosen-list.txt
#
# Then apply it:
#     ./scripts/load-blocklists.sh
#
# Two things to know before relying on it:
#
#   1. DNS blocking is domain-level. It cannot see inside HTTPS, so it stops a site
#      from loading but does nothing about material embedded in a site you allow.
#   2. AdGuard Home has its own "Parental control" category filter, switched on by
#      adguard/bootstrap.py. That is independent of this file and may be sufficient on
#      its own. Check it before adding an overlapping list — overlapping lists make
#      false positives considerably harder to diagnose.
